## MODIFIED Requirements

### Requirement: 运输计算器集成
系统必须与运输计算 API 集成，以提供透明的运输选项。

#### Scenario: 计算运输按钮位置
- **WHEN** 结算页面加载时
- **THEN** 在 Order Notes 字段下方显示 "Calculate Shipping" 按钮
- **AND** 将其置于显眼位置以提高用户可见性

#### Scenario: 运输选项显示
- **WHEN** 用户点击 "Calculate Shipping" 按钮时
- **THEN** 在按钮下方以表格形式显示所有可用的运输方式
- **AND** 为每个选项显示运输费用、交付时间和方式名称
- **AND** 预选第一个运输方式作为默认选项
- **AND** 允许用户选择其他运输方式

#### Scenario: API 通信透明性
- **WHEN** 显示运输选项时
- **THEN** 在 API 调用期间显示加载指示器
- **AND** 以结构化表格格式显示 API 响应数据
- **AND** 优雅地处理 API 错误并显示用户友好的消息

### Requirement: 运输选择和价格更新
系统必须根据选择的运输方式更新订单总价。

#### Scenario: 默认运输选择
- **WHEN** 运输选项显示时
- **THEN** 自动选择第一个可用的运输方式
- **AND** 更新订单总价以反映所选运输费用

#### Scenario: 运输方式变更
- **WHEN** 用户选择不同的运输方式时
- **THEN** 实时更新订单总价
- **AND** 在表格中突出显示所选运输方式
- **AND** 保持选择直到用户更改或完成订单

#### Scenario: 价格计算准确性
- **WHEN** 选择运输方式时
- **THEN** 将运输费用添加到产品总价中
- **AND** 显示包含税费和运费的最终订单总价
- **AND** 确保计算结果与 API 响应数据匹配

## ADDED Requirements

### Requirement: 增强的运输计算器界面
系统必须提供增强的用户界面，用于运输计算，具有改进的布局和交互。

#### Scenario: 按钮重新定位
- **WHEN** 结算页面渲染时
- **THEN** 将 Calculate Shipping 按钮直接定位在 Order Notes 字段下方
- **AND** 确保按钮在视觉上突出且易于访问
- **AND** 与其他表单元素保持一致的间距

#### Scenario: 综合运输显示
- **WHEN** 用户点击 Calculate Shipping 按钮时
- **THEN** 用综合表格视图替换简单的下拉菜单
- **AND** 同时显示所有可用的运输方式
- **AND** 为每种方式显示详细信息（名称、费用、预计交付）
- **AND** 提供默认选择方式的清晰视觉指示

#### Scenario: 交互式运输选择
- **WHEN** 运输选项表格显示时
- **THEN** 允许用户点击任何运输方式进行选择
- **AND** 为当前选择的运输方式提供视觉反馈
- **AND** 在选择变更时立即更新订单摘要
- **AND** 在整个结算过程中保持选择状态

### Requirement: API 响应透明性
系统必须向用户透明地显示 API 通信结果。

#### Scenario: 加载状态管理
- **WHEN** 点击 Calculate Shipping 按钮时
- **THEN** 显示加载旋转器或进度指示器
- **AND** 在 API 调用期间禁用按钮以防止多次请求
- **AND** 显示 "正在计算运输选项..." 消息

#### Scenario: API 结果展示
- **WHEN** API 调用成功完成时
- **THEN** 在格式化的表格中显示所有返回的运输方式
- **AND** 为每个选项显示方式名称、费用和交付时间
- **AND** 突出显示默认/推荐的方式
- **AND** 以用户货币提供清晰的定价

#### Scenario: 错误状态处理
- **WHEN** API 调用失败或返回错误时
- **THEN** 显示用户友好的错误消息
- **AND** 提供重新计算的选项
- **AND** 如果运输计算不可用则显示后备消息
- **AND** 记录技术细节以供调试

### Requirement: 响应式表格设计
系统必须为所有设备尺寸提供响应式表格设计。

#### Scenario: 移动端优化
- **WHEN** 在移动设备上查看时
- **THEN** 以移动友好的格式显示运输选项
- **AND** 确保表格在需要时可以水平滚动
- **AND** 保持运输费用和交付时间的可读性
- **AND** 保留触摸友好的选择界面

#### Scenario: 平板适配
- **WHEN** 在平板设备上查看时
- **THEN** 优化中等屏幕尺寸的表格布局
- **AND** 在信息密度和可用性之间取得平衡
- **AND** 确保选择控件易于访问
