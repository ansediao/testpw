# PW Canvas 项目文档

## 项目目的

PW Canvas 是一个基于 WordPress 的插件，为电商网站提供在线产品定制功能。该插件允许用户在网页上进行产品设计和定制，主要面向电商场景中的个性化产品定制需求。

### 核心功能
- **在线画布设计**: 基于 Fabric.js 的 2D 画布编辑器，支持图形、文字、图像等元素操作
- **产品变体管理**: 支持颜色、尺寸、材料等产品变体选择和价格计算
- **购物车集成**: 与 WooCommerce 深度集成，支持定制产品添加到购物车
- **设计管理**: 自定义文章类型 `pw_design` 用于管理设计模板和用户设计
- **API 集成**: 与 Promowares API 进行数据交互获取产品信息和打印方式

### 目标用户
- 电商网站管理员：安装配置插件，管理产品定制选项
- 终端消费者：在产品页面进行个性化定制，预览效果，提交订单

## 技术栈

### 后端技术
- **PHP 5.6+**: 遵循 WordPress 插件开发标准，确保向下兼容
- **WordPress**: 插件架构，使用 WordPress Hook 系统进行功能扩展
- **WooCommerce**: 电商功能集成，支持产品变体和购物车功能
- **MySQL**: 数据存储（通过 WordPress）

### 前端技术
- **Vue 3**: 主要前端框架，使用 Composition API 进行组件开发
- **Pinia**: 状态管理库，用于管理应用状态和数据流
- **Fabric.js**: 2D 画布编辑和图形处理，提供设计功能核心
- **Axios**: HTTP 客户端，用于前后端数据通信
- **jsPDF**: PDF 导出功能，支持设计效果导出
- **Three.js**: 3D 模型展示（通过 CDN 加载）
- **MicroModal.js**: 弹窗组件库，提供统一的用户交互体验

### 外部依赖
- **CDN 资源**: Vue 3, Pinia, Fabric.js, Three.js 等通过 CDN 加载
- **阿里云字体图标**: 图标资源
- **Promowares API**: 外部数据服务，提供产品信息和打印方式数据

### 开发工具
- **Git**: 版本控制
- **WordPress 开发环境**: 本地开发需要 WordPress 环境
- **SCSS**: 样式预处理，支持变量和混合器

## 项目规范

### 代码风格

#### 命名防冲突规范
项目统一使用 **`pwca`** (PW Canvas) 作为防冲突前缀，避免与其他插件冲突：

- **CSS 类名和 ID**: 使用 `pwca-` 前缀
- **JavaScript 全局函数**: 使用 `pwca` 前缀
- **WordPress 钩子**: 使用 `pwca_` 前缀
- **REST API 端点**: 使用 `pwca/v1` 命名空间
- **数据库表和选项**: 使用 `pwca_` 前缀

#### PHP 规范
- **类名**: 大驼峰命名法，以 `Pw_Admin` 前缀开始
- **方法和函数**: 小驼峰命名法，具有描述性
- **变量**: 小驼峰命名法，使用描述性名词
- **文件**: 小写连字符分隔，类文件使用 `class-` 前缀
- **注释**: 必须遵循 PHPDoc 规范，包含完整文档注释

#### JavaScript 规范
- **函数**: 小驼峰命名法，动词开头
- **变量**: 小驼峰命名法，描述性名词
- **常量**: 大写下划线分隔
- **全局函数和变量**: 使用 `pwca` 前缀避免冲突
- **注释**: 必须遵循 JSDoc 规范

#### CSS/SCSS 规范
- **全局类名**: 使用 `pwca-` 前缀
- **BEM 命名规范**: 必须使用 BEM 方法论
- **变量集中管理**: 所有变量定义在 `public/css/_variables.scss`
- **混合器管理**: 混合器定义在 `public/css/_mixins.scss`
- **文件结构**: 必须完全符合对应模块的 DOM 结构

### 架构模式

#### 模块化设计
- **前端组件化**: Vue 3 组件化架构，按功能模块组织
- **后端类文件分离**: 每个功能模块对应独立的 PHP 类文件
- **关注点分离**: 严格区分前后台逻辑，核心逻辑与展示逻辑分离

#### Hook 驱动架构
- 使用 WordPress Hook 系统进行功能扩展
- 事件驱动的组件通信机制
- 插件化架构支持功能模块的动态加载

#### 前后端分离
- **数据通信**: 通过 WordPress REST API 进行前后端通信
- **状态管理**: 使用 Pinia 进行前端状态管理
- **API 代理**: 所有第三方 API 调用必须通过后端代理

#### 统一弹窗系统
- **MicroModal.js**: 前后台统一使用 MicroModal.js 弹窗库
- **CDN引入**: 通过 `public/modules/class-pw-cdn-loader.php` 统一引入
- **标准化结构**: 所有弹窗遵循统一的HTML结构和API规范
- **可访问性**: 提供标准化的键盘导航和屏幕阅读器支持

## 领域上下文

### 电商产品定制
- **产品定制流程**: 用户选择产品 → 进入设计界面 → 添加设计元素 → 预览效果 → 提交订单
- **设计元素**: 支持文字、图像、图形、颜色等设计元素
- **产品变体**: 颜色、尺寸、材料、打印方式等变体选项
- **价格计算**: 基于产品基础价格和定制选项的动态价格计算

### WordPress 插件开发
- **插件架构**: 遵循 WordPress 插件开发最佳实践
- **数据库设计**: 使用 WordPress 数据库标准和命名规范
- **用户权限**: 利用 WordPress 用户系统和权限管理
- **多语言支持**: 使用 WordPress 国际化框架

### 前端交互设计
- **响应式设计**: 支持桌面和移动设备访问
- **实时预览**: 设计变更实时反映在预览区域
- **拖拽操作**: 支持设计元素的拖拽和定位
- **图层管理**: 类似 Photoshop 的图层系统

### 页面类型定义

#### 产品页 (Product Pages)
- **路径模式**: `/product/{产品名}/`
- **功能**: WordPress标准产品展示页面
- **样式文件**: 在 `public/modules/class-pw-cdn-loader.php` 中引用
- **组件位置**: `public/js/product/components/`
- **状态管理**: `public/js/product/stores/`

#### 设计页 (Design Pages)
- **路径模式**: `/pwcanvas/?product_id=xxx`
- **功能**: 在线产品定制页面
- **页面模板**: `public/partials/template-canvas-display.php`
- **组件位置**: `public/js/design/components/`
- **状态管理**: `public/js/design/stores/`

#### 页面组件架构
- **组件分离**: 产品页和设计页组件完全分离
- **状态隔离**: 不同页面类型使用独立的状态管理
- **样式独立**: 各页面类型有独立的样式文件
- **功能解耦**: 避免页面间功能相互依赖

## 重要约束

### 技术约束
- **PHP 兼容性**: 必须兼容 PHP 5.6 及以上版本
- **WordPress 版本**: 支持主流 WordPress 版本
- **浏览器兼容性**: 支持现代浏览器（Chrome、Firefox、Safari、Edge）
- **移动端支持**: 响应式设计支持移动设备

### 业务约束
- **性能要求**: 画布操作响应时间 < 100ms
- **内存限制**: 避免大文件上传和处理
- **安全要求**: 防止 XSS、CSRF 等安全攻击
- **数据验证**: 严格的前后端数据验证

### 命名冲突约束
- **防冲突前缀**: 所有全局命名必须使用 `pwca` 前缀
- **WordPress 兼容**: 避免与常见插件（WooCommerce、Elementor等）冲突
- **CSS 隔离**: 确保样式不会被其他主题或插件意外覆盖
