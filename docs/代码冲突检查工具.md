# 代码冲突检查工具

## 概述

本文档提供了一系列检查工具和脚本，用于识别 PW Canvas 项目中可能存在命名冲突风险的代码。

## 自动化检查脚本

### 1. CSS 类名和 ID 检查

#### Windows PowerShell 脚本
```powershell
# 检查没有使用 pwca- 前缀的全局CSS类名
Write-Host "=== 检查可能冲突的CSS类名 ===" -ForegroundColor Yellow
Get-ChildItem -Path "modules\" -Recurse -Include "*.css", "*.scss" | 
    ForEach-Object {
        $content = Get-Content $_.FullName
        $lineNumber = 0
        foreach ($line in $content) {
            $lineNumber++
            # 查找可能的全局类名（不以 pwca- 开头的）
            if ($line -match '\.(?!pwca-)([a-z][a-z-]*)\s*\{') {
                Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Red
            }
        }
    }

# 检查没有使用 pwca- 前缀的ID选择器
Write-Host "`n=== 检查可能冲突的ID选择器 ===" -ForegroundColor Yellow
Get-ChildItem -Path "modules\", "includes\" -Recurse -Include "*.css", "*.scss", "*.php" | 
    ForEach-Object {
        $content = Get-Content $_.FullName
        $lineNumber = 0
        foreach ($line in $content) {
            $lineNumber++
            if ($line -match '#(?!pwca-)([a-z][a-z-]*)\s*[\{\s]') {
                Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Red
            }
        }
    }
```

#### Linux/Mac 脚本
```bash
#!/bin/bash

echo "=== 检查可能冲突的CSS类名 ==="
find modules -name "*.css" -o -name "*.scss" | xargs grep -n '\.(?!pwca-)[a-z][a-z-]*\s*{' || echo "未发现问题"

echo -e "\n=== 检查可能冲突的ID选择器 ==="
find modules includes -name "*.css" -o -name "*.scss" -o -name "*.php" | xargs grep -n '#(?!pwca-)[a-z][a-z-]*\s*[{]' || echo "未发现问题"
```

### 2. JavaScript 全局函数检查

#### PowerShell 脚本
```powershell
Write-Host "=== 检查可能冲突的全局JavaScript函数 ===" -ForegroundColor Yellow

# 检查全局函数定义
Get-ChildItem -Path "modules\" -Recurse -Include "*.js" | 
    ForEach-Object {
        $content = Get-Content $_.FullName
        $lineNumber = 0
        foreach ($line in $content) {
            $lineNumber++
            # 检查全局函数定义（不以 pwca 开头）
            if ($line -match 'function\s+(?!pwca)([a-z][a-zA-Z]*)\s*\(') {
                Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Red
            }
            # 检查 window 对象赋值
            if ($line -match 'window\.(?!pwca)([a-z][a-zA-Z]*)\s*=') {
                Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Red
            }
        }
    }
```

#### Linux/Mac 脚本
```bash
#!/bin/bash

echo "=== 检查可能冲突的全局JavaScript函数 ==="

# 检查全局函数定义
find modules -name "*.js" | xargs grep -n 'function\s\+[a-z][a-zA-Z]*\s*(' | grep -v 'pwca' || echo "未发现问题"

# 检查 window 对象赋值
find modules -name "*.js" | xargs grep -n 'window\.[a-z][a-zA-Z]*\s*=' | grep -v 'pwca' || echo "未发现问题"
```

### 3. WordPress 钩子和选项检查

#### PowerShell 脚本
```powershell
Write-Host "=== 检查WordPress钩子和选项命名 ===" -ForegroundColor Yellow

Get-ChildItem -Path ".", "includes\", "modules\" -Recurse -Include "*.php" | 
    ForEach-Object {
        $content = Get-Content $_.FullName
        $lineNumber = 0
        foreach ($line in $content) {
            $lineNumber++
            # 检查可能冲突的钩子名称
            if ($line -match "(add_action|add_filter)\s*\(\s*['\"](?!wp_|pwca_)([a-z_]+)['\"]") {
                if (-not ($line -match "(wp_|init|admin_|wp_ajax)")) {
                    Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Red
                }
            }
            # 检查选项名称
            if ($line -match "(get_option|update_option|delete_option)\s*\(\s*['\"](?!pwca_)([a-z_]+)['\"]") {
                Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Yellow
            }
        }
    }
```

### 4. 事件名称检查

#### PowerShell 脚本
```powershell
Write-Host "=== 检查自定义事件命名 ===" -ForegroundColor Yellow

Get-ChildItem -Path "modules\" -Recurse -Include "*.js" | 
    ForEach-Object {
        $content = Get-Content $_.FullName
        $lineNumber = 0
        foreach ($line in $content) {
            $lineNumber++
            # 检查 CustomEvent 创建
            if ($line -match "new\s+CustomEvent\s*\(\s*['\"](?!pwca)([a-zA-Z]+)['\"]") {
                Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Red
            }
            # 检查 addEventListener 自定义事件
            if ($line -match "addEventListener\s*\(\s*['\"](?!pwca)([a-zA-Z]+)['\"]") {
                if (-not ($line -match "(click|load|ready|resize|scroll|DOMContent)")) {
                    Write-Host "$($_.Name):$lineNumber - $line" -ForegroundColor Red
                }
            }
        }
    }
```

## 手动检查清单

### 高风险冲突项目

#### 1. 全局 JavaScript 函数
检查这些常见的容易冲突的函数名：
- [ ] `init()` → 应为 `pwcaInit()`
- [ ] `render()` → 应为 `pwcaRender()`
- [ ] `save()` → 应为 `pwcaSave()`
- [ ] `load()` → 应为 `pwcaLoad()`
- [ ] `export()` → 应为 `pwcaExport()`

#### 2. CSS 类名和 ID
检查这些常见的容易冲突的选择器：
- [ ] `.container` → 应为 `.pwca-container`
- [ ] `.toolbar` → 应为 `.pwca-toolbar`
- [ ] `.panel` → 应为 `.pwca-panel`
- [ ] `#app` → 应为 `#pwca-app`
- [ ] `#main` → 应为 `#pwca-main`

#### 3. 事件名称
检查这些常见的容易冲突的事件：
- [ ] `ready` → 应为 `pwcaReady`
- [ ] `loaded` → 应为 `pwcaLoaded`
- [ ] `changed` → 应为 `pwcaChanged`
- [ ] `saved` → 应为 `pwcaSaved`

### 中风险冲突项目

#### 1. WordPress 钩子
- [ ] `after_*` → 应为 `pwca_after_*`
- [ ] `before_*` → 应为 `pwca_before_*`
- [ ] 自定义钩子名称

#### 2. Ajax 动作
- [ ] `save_*` → 应为 `pwca_save_*`
- [ ] `load_*` → 应为 `pwca_load_*`
- [ ] `delete_*` → 应为 `pwca_delete_*`

## 使用 IDE 工具检查

在 VS Code 中使用正则表达式搜索潜在冲突：

#### 1. 查找可能冲突的CSS类名
```regex
\.[a-z][a-z-]*(?<!pwca-[a-z-]*)\s*\{
```

#### 2. 查找可能冲突的JavaScript函数
```regex

```

#### 3. 查找可能冲突的事件名称
```regex
new\s+CustomEvent\s*\(\s*['"](?!pwca)[a-zA-Z]+['"]
```

## 重构建议

### 优先级排序

#### 立即处理（高风险）
1. **全局 JavaScript 函数** - 容易被其他脚本覆盖
2. **主要 CSS 类名** - 影响页面布局和样式
3. **自定义事件名称** - 可能与其他插件事件冲突

#### 逐步处理（中风险）
1. **WordPress 钩子名称** - 可能影响插件兼容性
2. **Ajax 动作名称** - 可能被其他插件调用
3. **REST API 端点** - URL 命名空间冲突

#### 可选处理（低风险）
1. **内部变量名** - 作用域内的命名
2. **私有方法名** - 模块内部使用
3. **组件内部状态** - Vue 组件内部

### 重构工具脚本

#### 批量重命名脚本示例
```powershell
# 批量重命名CSS类名
Get-ChildItem -Path "modules\" -Include "*.scss" -Recurse | 
    ForEach-Object {
        $content = Get-Content $_.FullName -Raw
        # 将 .container 替换为 .pwca-container
        $content = $content -replace '\.container\b', '.pwca-container'
        Set-Content $_.FullName $content
    }
```

## 总结

定期使用这些检查工具可以：

1. **提前发现冲突风险** - 在部署前识别问题
2. **维护代码质量** - 确保命名规范一致性
3. **避免生产问题** - 减少与其他插件的兼容性问题
4. **提高开发效率** - 自动化检查节省人工时间

建议将这些检查集成到 CI/CD 流程中，在每次提交时自动运行检查。
