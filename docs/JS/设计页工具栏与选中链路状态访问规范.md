# 设计页工具栏与选中链路状态访问规范

## 适用范围

- `modules/front_canvas/assets/js/main/ui-state-access.js`
- `modules/front_canvas/assets/js/main/dongtai-toolbar.js`
- `modules/front_canvas/assets/js/main/events.js`

## 目标

- 统一工具栏与选中事件对“当前画布 / 当前选中对象 / 当前激活 tab”的读取入口
- 消除 `selection:created` 与 `selection:updated` 的重复分支
- 避免外围脚本再各自维护一套激活画布与当前对象获取逻辑

## 共享状态入口

- 外围脚本统一优先使用 `window.pwcaUiStateAccess`
- 当前与工具栏、选中链路直接相关的入口包括：
  - `getActiveCanvas()`
  - `getActiveObject()`
  - `getCurrentActiveTab()`
  - `getActiveObjectType()`

## 实施规则

- `dongtai-toolbar.js` 不再直接自己拼装 `CanvasManager / getActiveCanvas / window.canvas` 读取链，统一改走 `pwcaUiStateAccess`
- `events.js` 中 `selection:created` 与 `selection:updated` 必须复用同一个选中处理函数
- 选中处理函数只负责：
  - 同步动态工具栏
  - 按对象类型切换操作面板 tab
  - 保留来自图层面板选中的兼容分支
- 若后续还有脚本需要读取当前选中对象，先补 `ui-state-access.js`，再接入业务脚本

## 兼容策略

- `ui-state-access.js` 允许保留 `window.canvas` / `window.fabricCanvas` 的兜底，避免旧初始化时序下工具栏失效
- 本阶段不重写动态工具栏业务，只收口状态读取与重复事件逻辑
- 旧的全局方法如 `switchOperationPanelTab()`、`updateDynamicToolbar()` 继续保留，由共享访问层负责衔接状态读取
