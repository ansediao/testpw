# 设计页产品数据请求与状态分层规范

## 适用范围

- `modules/front_canvas/assets/js/design/stores/index.js`
- `modules/front_canvas/assets/js/design/api/product-data-api.js`
- `modules/front_canvas/assets/js/design/stores/product-data-mapper.js`

## 职责边界

- `product-data-api.js` 负责：
  - 请求 `/wp-json/pw/v1/product-data/{pwId}`
  - 读取响应头中的缓存标记
  - 统一抛出请求错误
- `product-data-mapper.js` 负责：
  - 视图名 Unicode 兼容清洗
  - 图层 `imageURL` 标准化
  - 店铺配置提取与视图配置合并
  - 字体、模块、字段显示等产品数据派生规则
  - 从产品数据构建设计页 `views` 所需结构
- `useCanvasStore` 负责：
  - 调用 API 层拿原始数据
  - 调用 mapper 层清洗并生成设计页需要的数据
  - 将结果写入 `productData`、`storeCustomizationSettings`、`views`、`activeViewId`

## 设计原则

- store 不直接写底层 `fetch`
- store 不直接处理 HTTP 响应头细节
- store 不直接内嵌大段产品数据清洗逻辑
- mapper 只做数据转换，不写状态，不操作 DOM
- API 层只做请求，不更新 store

## 调用链规范

- 获取产品数据时按以下顺序处理：
  - `fetchCanvasProductData(pwId)`
  - `pwcaPrepareCanvasProductData(productData)`
  - `setProductData(...)`
  - `setStoreCustomizationSettings(...)`
  - `setViewsFromProductData(productData)`
- 构建视图时统一使用：
  - `pwcaBuildViewsFromProductData(productData, storeCustomizationSettings)`

## 兼容要求

- 必须继续兼容 Promowares `uXXXX` 与 `\uXXXX` 视图名
- 必须继续兼容图层 `imageURL` 的中文路径、包裹引号、首尾空格
- 必须继续遵守：
  - `custom_view` 视图配置优先于店铺默认配置
  - 店铺默认配置优先于插件内置默认值
- `window.pwcaBuildMergedLayerControls`
  - `window.pwcaExtractStoreCustomizationSettings`
  仍保留给旧脚本使用
