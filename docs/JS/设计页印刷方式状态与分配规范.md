# 设计页印刷方式状态与分配规范

## 适用范围

- `modules/front_canvas/assets/js/design/stores/printMethodStore.js`
- `modules/front_canvas/assets/js/design/components/layers/print-methods.js`
- `modules/front_canvas/assets/js/design/components/layers/print-method-assignment-service.js`

## 职责边界

- `printMethodStore` 只负责：
  - 印刷方式列表数据
  - 当前选中印刷方式
  - 图层与图层组到印刷方式的映射
  - 已使用印刷方式的统计与重算
  - 纯校验逻辑
- `print-method-assignment-service` 负责：
  - 图层切换印刷方式时的组创建与组复用
  - 图层 / 图层组重挂到新组
  - 画布对象重新校验与重定位
  - 触发需要兼容旧逻辑的事件
- `design/api/print-method-api.js` 负责：
  - 请求印刷方式接口
  - 请求印刷颜色列表接口
- `print-method-mapper.js` 负责：
  - 将后端印刷方式数据转换为前端内部结构
  - 将颜色数据合并到内部印刷方式对象
- `print-methods.js` 只负责：
  - 弹窗状态
  - 用户选择
  - 调用 service 并反馈错误

## 设计原则

- store 不直接操作 `CanvasManager`
- store 不直接调用 `PrintAreaValidator`
- store 不直接读取 DOM
- store 尽量不隐式读取其它 store；需要当前视图或当前图层列表时，优先由调用方显式传入
- store 不直接编写底层 `fetch` 细节，也不直接负责接口响应结构兼容
- 组件不直接改 store 的内部映射对象，只通过 store action 或 service 完成
- 当图层或图层组的印刷方式发生变化后，统一调用 `recomputeUsedPrintMethodsForView(viewId, viewLayers)` 重算已使用集合

## API 与数据分层规范

- API 文件只负责请求和错误抛出，不负责更新 store
- mapper 文件只负责把 API 数据转换为设计页内部格式
- store 负责调用 API 与 mapper，并把最终结果写入 state
- 组件不得直接请求 `/wp-json/pw-canvas/v1/print-methods` 或 `/custom-colors`

## 输入边界规范

- `setViewPrintMethods(viewId, printingMethodIds, { activeViewId })`
  - 由调用方显式传入当前激活视图，避免 store 内部再去读取 `useCanvasStore()`
- `recomputeUsedPrintMethodsForView(viewId, viewLayers)`
  - 由调用方显式传入当前视图的图层数组
- `restorePrintMethodMappings(viewId, { layerMap, groupMap, viewLayers })`
  - 恢复映射时同时传入视图图层，保证“已使用印刷方式”统计能够在单一入口完成

## 权限判断规范

- 图层复制/删除权限优先从：
  - `layerPrintMethodMap`
  - 图层对象上的 `groupId`
  - `groupPrintMethodMap`
  - `print-method-*` 组名约定
  依次解析
- 因此权限判断应尽量传入完整 `layer` / `group` 对象，而不是只传 `id`

## 分配流程规范

- 单图层切换印刷方式时：
  - 先验证图层是否支持目标印刷方式
  - 再决定是合并进现有组还是单独创建组
  - 更新图层 `groupId / printMethodId / groupOrder`
  - 更新 store 映射
  - 重算当前视图已使用印刷方式
  - 对当前视图对应 Fabric 对象做 Print Area 校验
- 图层组切换印刷方式时：
  - 先验证组内所有图层
  - 创建或复用目标印刷方式组
  - 统一迁移组内图层
  - 清理空组
  - 重算当前视图已使用印刷方式

## 兼容约束

- 保留 `pwcaGroupPrintMethodChanged` 事件
- 保留 `print-method-*` 作为组 ID 约定
- 旧代码若只依赖 store getter，仍然可以工作
- 新代码禁止把“映射更新 + 组创建 + 画布验证”重新塞回 store
