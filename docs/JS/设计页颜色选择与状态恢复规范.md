# 设计页颜色选择与状态恢复规范

## 适用范围

- `modules/front_canvas/assets/js/design/stores/index.js`
- `modules/front_canvas/assets/js/design/stores/color-selection-helper.js`
- `modules/front_canvas/assets/js/design/utils/canvas-state-manager.js`

## 职责边界

- `color-selection-helper.js` 负责：
  - 标准化 `selectedColorsByView`
  - 标准化单个颜色选择对象
  - 计算 `rts_for_bulk_order` / `rts_for_sample_order` 汇总值
  - 颜色选择 map 的增删改查
- `useCanvasStore` 负责：
  - 暴露 getter 与 action
  - 调用 helper 处理颜色选择 state
- `canvas-state-manager.js` 负责：
  - 保存颜色选择到持久化状态
  - 迁移旧状态中的颜色选择字段
  - 恢复颜色选择到 store

## 设计原则

- store 不直接裸写 `selectedColorsByView[viewId] = colorData`
- 保存前、恢复前、迁移后统一执行颜色选择标准化
- 恢复颜色选择优先走批量入口 `replaceSelectedColorsByView(...)`
- getter 中的 RTS 汇总逻辑统一复用 helper，不重复手写遍历

## 恢复链路规范

- 旧状态迁移时：
  - `selectedColorsByView` 必须被标准化为普通对象
- 保存状态时：
  - 先标准化 `selectedColorsByView`
  - 再写入持久化 state
- 恢复状态时：
  - 先标准化 `selectedColorsByView`
  - 再批量写回 `useCanvasStore`

## 兼容要求

- 保留 `selectedColorsByView` 的现有数据结构，不裁剪业务字段
- 保留 `window.pwcaNormalizeSelectedColorsByView` 给非模块脚本复用
- 产品页底部价格、MOQ、交期等依赖 `selectedColorsByView` 的逻辑不应受影响
