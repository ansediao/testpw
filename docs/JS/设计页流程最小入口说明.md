# 设计页流程最小入口说明

## 先记 4 个文件

如果你只想快速判断“设计页现在怎么跑”，先只看这 4 个文件：

- `modules/front_canvas/assets/js/canvas/page-bootstrap.js`
  - 设计页启动总入口
  - 当前同时承担 3 组页面级辅助能力：
    - 异步启动队列辅助
    - 加入购物车 payload 组装
    - PDF 导出与编辑态恢复
  - 现在优先看这几个 helper：
    - `buildStartupTasks`
    - `pwcaRunStartupQueueWithVueUse`
    - `buildAddToCartRequestBody`
    - `submitAddToCartRequest`
    - `toggleVisibleViewContainer`
    - `syncGlobalCanvasForView`
    - `resolveCartEditKey`
    - `waitForCanvasStateIntegration`
- `modules/front_canvas/assets/js/design/stores/index.js`
  - 设计页状态总入口
  - 负责把接口数据变成前端视图状态
- `modules/front_canvas/assets/js/canvas/multi-view-init.js`
  - 画布初始化总入口
  - 负责创建视图容器、初始化画布、按流程分支
  - 现在优先看这几个 helper：
    - `getCanvasDimensionsForView`
    - `buildCanvasConfigsForView`
    - `renderCanvasConfigsForView`
    - `applyFlowPostInitialization`
- `modules/front_canvas/assets/js/main/view-flow-resolver.js`
  - 流程识别总入口
  - 负责统一判断当前是不是 `4-Grid Flow`

## 再记 3 个 4 格图相关文件

如果你要看 `4-Grid Flow` 的特殊行为，再补看这 3 个文件：

- `modules/front_canvas/assets/js/design/utils/print-area-validator.js`
  - 控制拖拽边界和回正逻辑
- `modules/front_canvas/assets/js/main/tab-image.js`
  - 控制图片上传和四格图落点逻辑
- `modules/front_canvas/assets/js/main/grid-preview.js`
  - 控制 4 格图预览和导出拼图

## 当前最简流程

### 1. 页面启动

- `page-bootstrap.js`
- 当前应拆成 3 块理解：
  - 启动辅助：`pwcaCreateAsyncContext`、`buildStartupTasks`、`pwcaRunStartupQueue`
  - 提交辅助：`buildAddToCartRequestBody`、`submitAddToCartRequest`
  - 导出 / 恢复辅助：`syncGlobalCanvasForView`、`waitForCanvasStateIntegration`
- 如果只想看启动主干，先看两段：
  - `const tasks = buildStartupTasks(context);`
  - `useAsyncQueue(tasks, { ...配置项 })`

### 2. 数据成型

- `stores/index.js`
- 核心动作：
  - `fetchProductData(pwId)`
  - `setViewsFromProductData(data)`
  - `setProductViewFlow(viewFlow)`

### 3. 流程识别

- `view-flow-resolver.js`
- 统一通过：
  - `window.pwcaResolveViewFlow(view, store)`
  - `window.pwcaIsFourGridFlow(view, store)`

### 4. 画布初始化

- `multi-view-init.js`
- 核心动作：
  - `getCanvasDimensionsForView` 统一取尺寸
  - `buildCanvasConfigsForView` 统一分发图层
  - `renderCanvasConfigsForView` 统一渲染各层 canvas
  - `applyFlowPostInitialization` 统一执行流程后处理

## 平面流程和 4 格图流程差别只看一行

- 平面流程：
  - 初始化完后 `clearContentAreaClip(view.id)`
- `4-Grid Flow`：
  - 初始化完后 `handleFourGridContentArea(view)`

## 后面加新流程最少改哪里

如果要加 `Cylinder Flow` 这类新流程，最少先改这几处：

- `view-flow-resolver.js`
  - 新增统一判断 helper
- `multi-view-init.js`
  - 新增初始化分支
- `print-area-validator.js`
  - 新增边界规则
- `grid-preview.js` 或对应预览文件
  - 新增导出 / 预览规则

## 4 格图初始化出问题先查哪里

优先顺序固定：

- 先查 `view-flow-resolver.js`
  - 有没有识别错流程
- 再查 `multi-view-init.js`
  - 尺寸参考层对不对
  - 内容区域参考层对不对
  - 哪些图层被跳过了
- 再查 `print-area-validator.js`
  - 拖拽边界是不是还沿用旧规则
- 最后查 `grid-preview.js`
  - 是不是页面正常但预览导出不正常

## 一句话理解

- 你以后可以把设计页理解成：
  - `page-bootstrap.js` 负责启动
  - `stores/index.js` 负责数据
  - `view-flow-resolver.js` 负责识别流程
  - `multi-view-init.js` 负责画布落地
