# PW Canvas 防冲突命名规范

## 概述

为避免与其他WordPress插件、主题或核心功能产生命名冲突，PW Canvas项目统一使用 **`pwca`** (PW Canvas) 作为防冲突前缀。本文档详细说明在不同场景下的具体命名规范。

## 前缀使用策略

### 主要前缀
- **`pwca`** - 主要前缀，用于JavaScript、CSS、事件等
- **`pwca_`** - WordPress相关（下划线分隔）
- **`pwca-`** - CSS相关（连字符分隔）
- **`Pw_Admin`** - PHP类名（保持现有约定）

## 详细命名规范

### 1. CSS 样式规范

#### 全局CSS类名 - 必须使用 `pwca-` 前缀
```css
/* ✅ 正确 - 使用 pwca- 前缀 */
.pwca-canvas-container { }
.pwca-toolbar { }
.pwca-layer-panel { }
.pwca-design-area { }
.pwca-operation-panel { }
.pwca-color-picker { }
.pwca-modal-dialog { }

/* ❌ 错误 - 通用名称容易冲突 */
.canvas-container { }
.toolbar { }
.layer-panel { }
.design-area { }
```

#### 全局ID选择器 - 必须使用 `pwca-` 前缀
```css
/* ✅ 正确 */
#pwca-main-canvas { }
#pwca-preview-area { }
#pwca-design-workspace { }
#pwca-app-container { }

/* ❌ 错误 */
#main-canvas { }
#preview-area { }
#app { }
```

#### 组件内部类名 - 可保持现有命名
```css
/* ✅ 允许 - 组件内部作用域 */
.pwca-layer-panel .layer-item { }
.pwca-toolbar .toolbar-button { }
.pwca-design-area .design-thumbnail { }
```

### 2. JavaScript 规范

#### 全局函数 - 必须使用 `pwca` 前缀
```javascript
// ✅ 正确 - 全局函数使用前缀
function pwcaInitCanvas() { }
function pwcaSaveDesign() { }
function pwcaLoadTemplate() { }
function pwcaExportImage() { }
function pwcaAddLayer() { }

// ❌ 错误 - 通用名称容易冲突
function init() { }
function saveDesign() { }
function exportImage() { }
```

#### 全局变量和对象 - 挂载到 `window.pwca*`
```javascript
// ✅ 正确 - 全局命名空间
window.pwcaCanvasManager = { };
window.pwcaConfig = { };
window.pwcaStore = { };
window.pwcaUtils = { };

// ❌ 错误 - 直接使用全局变量
window.canvasManager = { };
window.config = { };
```

#### 模块内部函数 - 保持现有命名
```javascript
// ✅ 允许 - 模块内部作用域
(function() {
    function initializeCanvas() { } // 内部函数
    function updateToolbar() { }   // 内部函数
    
    // 只有导出的函数需要前缀
    window.pwcaInitSystem = function() {
        initializeCanvas();
        updateToolbar();
    };
})();
```

### 3. 事件命名规范

#### 自定义事件 - 必须使用 `pwca` 前缀
```javascript
// ✅ 正确 - 自定义事件使用前缀
document.dispatchEvent(new CustomEvent('pwcaCanvasReady'));
document.dispatchEvent(new CustomEvent('pwcaDesignSaved'));
document.dispatchEvent(new CustomEvent('pwcaLayerAdded'));
document.dispatchEvent(new CustomEvent('pwcaViewChanged'));

// ❌ 错误 - 通用事件名容易冲突
document.dispatchEvent(new CustomEvent('canvasReady'));
document.dispatchEvent(new CustomEvent('designSaved'));
```

### 4. WordPress 相关规范

#### 钩子和过滤器 - 使用 `pwca_` 前缀
```php
// ✅ 正确 - WordPress钩子使用前缀
add_action('pwca_after_canvas_init', 'callback_function');
add_filter('pwca_canvas_settings', 'filter_function');
add_action('pwca_design_saved', 'save_callback');

// WordPress核心钩子不需要前缀
add_action('wp_enqueue_scripts', 'enqueue_scripts');
add_action('init', 'init_custom_post_types');
```

#### Ajax动作 - 使用 `pwca_` 前缀
```php
// ✅ 正确
add_action('wp_ajax_pwca_save_design', 'handle_save_design');
add_action('wp_ajax_nopriv_pwca_load_template', 'handle_load_template');

// JavaScript中对应的调用
$.post(ajaxurl, {
    action: 'pwca_save_design',
    data: designData
});
```

#### WordPress选项 - 使用 `pwca_` 前缀
```php
// ✅ 正确
update_option('pwca_api_settings', $settings);
get_option('pwca_canvas_config', $default);
delete_option('pwca_temp_data');

// ❌ 错误
update_option('api_settings', $settings);
get_option('canvas_config', $default);
```

#### 数据库表名 - 使用 `pwca_` 前缀
```php
// ✅ 正确 - 自定义表使用前缀
global $wpdb;
$table_name = $wpdb->prefix . 'pwca_designs';
$table_name = $wpdb->prefix . 'pwca_templates';
$table_name = $wpdb->prefix . 'pwca_user_preferences';
```

### 5. REST API 规范

#### API端点 - 使用 `pwca/` 或 `pw-canvas/` 前缀
```php
// ✅ 正确 - API命名空间使用前缀
register_rest_route('pwca/v1', '/designs', $args);
register_rest_route('pw-canvas/v1', '/templates', $args);
register_rest_route('pwca/v1', '/export', $args);

// ❌ 错误 - 通用命名空间
register_rest_route('canvas/v1', '/designs', $args);
register_rest_route('api/v1', '/templates', $args);
```

### 6. 自定义文章类型和分类法

#### 使用 `pw_` 前缀（保持现有约定）
```php
// ✅ 正确 - 保持现有约定
register_post_type('pw_design', $args);
register_taxonomy('pw_design_category', 'pw_design', $args);
register_taxonomy('pw_design_tag', 'pw_design', $args);
```

### 7. Vue 组件和 Pinia Store

#### 组件内部 - 保持现有命名
```javascript
// ✅ 允许 - Vue组件内部方法
export default {
    name: 'LayerPanel', // 组件名可保持现有
    methods: {
        addLayer() { },      // 内部方法
        deleteLayer() { },   // 内部方法
        toggleVisibility() { } // 内部方法
    }
}
```

#### Store导出 - 使用防冲突命名
```javascript
// ✅ 正确 - 全局Store使用前缀
const usePwcaCanvasStore = defineStore('pwcaCanvas', { });
const usePwcaProductStore = defineStore('pwcaProduct', { });

// 导出到全局
window.usePwcaCanvasStore = usePwcaCanvasStore;
window.usePwcaProductStore = usePwcaProductStore;
```

## 实施指南

### 渐进式迁移策略

1. **新功能**: 严格按照新规范命名
2. **现有功能**: 优先级排序逐步重构
   - 高风险：全局函数、CSS类名
   - 中风险：事件名称、API端点  
   - 低风险：内部变量、方法名

### 重构优先级

#### 高优先级（立即处理）
- [ ] 全局JavaScript函数
- [ ] 主要CSS类名和ID
- [ ] 自定义事件名称
- [ ] WordPress钩子和选项

#### 中优先级（逐步处理）
- [ ] Ajax动作名称
- [ ] REST API端点
- [ ] 数据库表字段

#### 低优先级（可选处理）
- [ ] 组件内部方法名
- [ ] 局部变量名
- [ ] 私有函数名

### 兼容性处理

在重构过程中，保持向后兼容：

```javascript
// 新的命名
function pwcaInitCanvas() {
    // 新的实现
}

// 向后兼容的别名
window.init = window.pwcaInitCanvas; // 临时兼容

// 弃用警告
window.init = function() {
    console.warn('init() is deprecated, use pwcaInitCanvas() instead');
    return pwcaInitCanvas.apply(this, arguments);
};
```

## 工具和检查

### 命名检查工具

```bash
# 检查可能的冲突风险
grep -r "function [a-z]" public/js/ --include="*.js"
grep -r "window\.[a-z]" public/js/ --include="*.js"
grep -r "class=\"[^p]" public/ --include="*.php"
```

## 常见问题

### Q: 什么情况下不需要使用前缀？
A: 模块内部、组件内部、闭包内部的私有函数和变量不需要前缀。

### Q: 如何处理第三方库的冲突？
A: 优先使用命名空间封装，将第三方库包装在自己的命名空间内。

### Q: Vue组件名称需要前缀吗？
A: 组件文件名和内部方法不需要，但全局注册的组件建议使用前缀。

### Q: 现有代码如何迁移？
A: 采用渐进式迁移，优先处理高风险的全局命名，保持向后兼容。

## 总结

防冲突命名规范的核心原则：
1. **全局可见的都要加前缀**
2. **内部作用域的可以保持原样**  
3. **优先级驱动的渐进式迁移**
4. **保持向后兼容性**
5. **使用工具自动化检查**

遵循这些规范可以有效避免与其他WordPress插件、主题的命名冲突，提高代码的可维护性和稳定性。
